## 🆕 Latest Project

#### 🎓 Training Center Platform (Backend)
![ASP.NET Core](https://img.shields.io/badge/ASP.NET--Core-5C2D91?style=for-the-badge&logo=.net&logoColor=white)
![C#](https://img.shields.io/badge/C%23-239120?style=for-the-badge&logo=c-sharp&logoColor=white)

![3-Tier Architecture](https://img.shields.io/badge/Architecture-3--Tier-0078D4?style=for-the-badge&logo=diagrams.net&logoColor=white)

A full-stack training center management system backend built for **learning and practicing professional backend development concepts**. This project leverages **ASP.NET Core Web API, Entity Framework Core, RESTful API design**, and strict **Layered Architecture**.

This system represents a major step in building realistic, scalable architectures similar to those used in real-world enterprise applications.

##### 🚀 Project Overview

The Training Center Platform provides a robust backend system designed to efficiently manage educational operations, including:
- 👨‍🎓 **Students** & 👤 **Student Profiles**
- 👨‍🏫 **Instructors**
- 📚 **Courses**
- 📝 **Enrollments**

The system exposes clean, well-documented APIs for managing entities, handling complex relational data, and ensuring a strict separation of concerns across application layers.

##### 🏛️ Architecture

The project strictly follows a **3-Tier Architecture** pattern to decouple the API endpoints from business rules and database operations:

```text
       [ Client / Frontend Application ]
                     │
                     ▼
       🌐 ASP.NET Core Web API Layer
          (Controllers, DTOs, Routing)
                     │
                     ▼
           🧠 Business Logic Layer
        (Services, Validation, Mapping)
                     │
                     ▼
           🗄️ Data Access Layer
    (EF Core, DbContext, Database Operations)
                     │
                     ▼
          🛢️ SQL Server Database
```

##### 📂 Solution Structure

| Project | Responsibility |
| --- | --- |
| `🌐 TrainingCenter.API` | Handles HTTP requests, Controllers, DTO routing, and API responses. |
| `🧠 TrainingCenter.Business` | Contains core business logic, object mapping, validation, and workflows. |
| `🗄️ TrainingCenter.Data` | Handles database communication and repository implementations using EF Core. |
| `🏛️ TrainingCenter.Entities` | Domain models and database schema definitions mapped from SQL Server. |

##### 🔥 Backend Concepts Practiced

###### 🌐 RESTful API Design
Implemented APIs strictly following REST principles:
* `GET` - Retrieve resources safely.
* `POST` - Create new resources.
* `PUT` - Fully update existing resources.
* `DELETE` - Remove resources.
* **Standardized Status Codes:** `200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`, `500 Internal Server Error`.

###### 🗄️ Entity Framework Core
Deep dive into database integrations, including:
* ✅ Custom `DbContext` configuration.
* ✅ Advanced **LINQ Queries** for data filtering.
* ✅ Complex **Entity Mapping** (One-to-One, One-to-Many, Many-to-Many).
* ✅ **AsNoTracking()** optimization for read-only queries.
* ✅ Fully **Asynchronous** database operations (`ToListAsync`, `FirstOrDefaultAsync`).

###### 📦 DTO Pattern (Data Transfer Object)
The API **never** exposes database entities directly to the client.

```text
Client ↔ DTO ↔ API Controller ↔ Business Logic ↔ Entity ↔ Database
```

**Benefits:**
* 🔒 **Better Security:** Prevents Over-Posting attacks.
* 📄 **Cleaner Contracts:** Delivers only the data the frontend actually needs.
* 🧩 **Flexibility:** Allows the database schema to change without breaking the API payload.

##### 🔐 Error Handling & Safety

Implemented centralized, safe database execution patterns to prevent application crashes and handle exceptions gracefully.

```csharp
// Example of the safe execution wrapper pattern used in the Data Access Layer
public async Task<Result<T>> ExecuteSafeAsync<T>(Func<Task<T>> action)
{
    try
    {
        var result = await action();
        return Result<T>.Success(result);
    }
    catch (SqlException ex)
    {
        // Log exception details
        return Result<T>.Failure("A database error occurred.");
    }
    catch (Exception ex)
    {
        // Log generic exception
        return Result<T>.Failure("An unexpected error occurred.");
    }
}
```
